## 答案

**正确答案：** (1) 2；(2) ① B；② 1；(3) ① `seat = j`；② `sta[seat][j] = 0`；③ `sta[seat][k] = s - k`

---

## 解析

本题的核心是把车票看成站点之间的区间占用，并用 `sta[i][k]` 维护第 `i` 个座位从第 `k` 站开始还能连续空闲多少个区间。购买 `s→e` 的车票占用的是 `s` 到 `e-1` 的区间，不占用到达站 `e`。

### （1）按订单分配座位

按提交时间处理订单，座位编号从 0 开始依次尝试：

| 订单 | 乘车区间 | 分配座位 | 判断 |
|---|---|---:|---|
| A01 | `0→2` | 0 | 0 号座位全程空闲 |
| A02 | `2→4` | 0 | A01 只占用 `[0,2)`，从 2 站开始可以复用 |
| B01 | `1→5` | 1 | 0 号座位在 `1→2`、`2→3`、`3→4` 处与已有订单冲突 |
| B02 | `4→5` | 0 | 0 号座位在 `4→5` 区间已经空闲 |
| A03 | `0→3` | 2 | 0、1 号座位均有冲突，2 号座位仍满足条件 |

因此，A03 被分配到 **2 号座位**。

### （2）合并两个有序订单列表

#### ① 判断应从哪个列表取出元素

当 `ods2` 已经取完时，必须直接取 `ods1`；否则还要保证 `i` 没有越界，并比较两个当前订单的提交时间。因此划线处为：

```python
i < len(ods1) and ods1[i][1] <= ods2[j][1]
```

对应选项 **B**。选项 A 没有正确保护 `i`，选项 C 使用 `or`，在 `i == len(ods1)` 时仍可能访问 `ods1[i]`。

#### ② 追踪指针 `j`

两组订单的提交时间分别为：

```text
ods1：A01(1)，A02(3)
ods2：B01(2)，B02(4)
```

归并顺序为 `A01 → B01 → A02 → B02`。添加前三个订单后，`ods1` 的两个元素都已比较并取出，`ods2` 只取出了 B01，所以 `j = 1`。

### （3）维护每个座位的连续空闲长度

初始化时，对 `n = 6` 个站点，每个座位的状态为：

```python
[5, 4, 3, 2, 1, 0]
```

例如 `sta[i][2] = 3` 表示该座位从第 2 站开始，连续空闲区间为 `2→3`、`3→4`、`4→5`。

#### ① 记录找到的座位

`j` 是当前检查的座位号，找到第一个满足 `sta[j][s] >= r` 的座位后，应记录：

```python
seat = j
```

#### ② 清除新订单占用的区间

订单占用 `s` 到 `e-1`，正好对应 `range(s, e)`，因此每个被占用位置置零：

```python
sta[seat][j] = 0
```

#### ③ 更新出发站之前的状态

新订单从 `s` 站开始占用后，出发站之前那些原本能一直空闲到 `s` 之后的位置，其连续空闲长度必须截断为到 `s` 为止的长度。若原值满足 `sta[seat][k] > s - k`，说明它原来的空闲区间跨过了 `s`，应改为：

```python
sta[seat][k] = s - k
```

一旦 `sta[seat][k] <= s - k`，说明该位置原本的空闲区间已经在 `s` 之前结束，可以停止向前更新。

例如订单 `2→4` 处理前状态为 `[5, 4, 3, 2, 1, 0]`。先将第 2、3 个位置清零，得到 `[5, 4, 0, 0, 1, 0]`；再从 `k = 1` 向前更新：`4 > 1`，改为 1；`5 > 2`，改为 2，最终为 `[2, 1, 0, 0, 1, 0]`。

所以第（3）问三个空依次为：

```python
seat = j
sta[seat][j] = 0
sta[seat][k] = s - k
```
